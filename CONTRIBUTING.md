# Contributing

1. Choose the correct numbered `Part-###` folder.
2. Keep examples focused on the learning objective and avoid unrelated dependency churn.
3. Do not commit secrets, private data, generated credentials, or proprietary third-party material.
4. Run lint, tests, accessibility checks where applicable, and a production build before requesting review.
5. Explain the user-visible or educational reason for the change and document compatibility/migration impact.
6. Preserve accessible semantics, security boundaries, and version-resilient guidance.
